# 도메인 간 의존성 분석 보고서

## 개요
domain-modules 디렉토리 내에서 다른 도메인의 entity나 repository를 import하고 있는 파일들을 분석하여 도메인 간 의존성을 파악했습니다.

## 주요 발견사항

### 1. 잘못된 import 패턴
분석 결과, 여러 도메인 모듈에서 `com.orangeschool.orangeschoolapiserver.domain` 패키지를 import하고 있습니다. 이는 모놀리식 구조의 레거시 코드로 보이며, 도메인 모듈화 원칙에 위배됩니다.

### 2. 도메인별 의존성 현황

#### member-domain
- **TownFriendService.java**
  - challenge 도메인 의존: `Challenge`, `ChallengeRepository`
  - cheering 도메인 의존: `CheeringRepository`
  - follow 도메인 의존: `FollowRepository`
  
- **CommonMemberService.java**
  - 다른 도메인에 대한 의존성 확인 필요

#### education-domain
- **ChallengeService.java**
  - member 도메인 의존: `CommonMember`, `CommonMemberRepository`
  - support 도메인 의존: `MemberAlarmService`
  
- **MemberAcademyService.java**, **AcademyService.java**
  - member 도메인에 대한 의존성 존재
  
- **SchoolScheduleService.java**
  - 의존성 확인 필요

#### support-domain
- **AlarmService.java**
  - member 도메인 의존: `MemberAlarmService`
  
- **ReportService.java**
  - member 도메인 의존: `CommonMember`, `CommonMemberRepository`
  - story 도메인 의존: `Story`, `StoryComment`, `StoryReply` 및 관련 repository들
  - pick 도메인 의존: `PickComment`, `PickReply` 및 관련 repository들
  
- **기타 서비스들**
  - BannerService, VisitorService, NoticeService 등도 member 도메인에 의존

#### schedule-domain
- **ScheduleService.java**
  - member 도메인 의존: `CommonMember`, `CommonMemberRepository`
  - education 도메인 의존: `Academy`, `AcademyRepository`, `MemberAcademy`, `MemberAcademyRepository`
  - support 도메인 의존: `MemberAlarmService`
  - calendar 도메인 의존: `Calendar`, `CalendarService`, `CalendarRepository`
  
- **ScheduleTempService.java**
  - member 도메인에 대한 의존성 존재

#### community-domain
- **CheeringService.java**
  - member 도메인 의존: `CommonMember`, `CommonMemberRepository`
  
- **FollowService.java**
  - member 도메인에 대한 의존성 존재

## 문제점

1. **순환 의존성 위험**: 여러 도메인이 서로를 참조하고 있어 순환 의존성 발생 가능
2. **도메인 경계 위반**: 도메인 모듈화의 목적인 독립성과 응집성이 훼손됨
3. **레거시 코드 혼재**: `com.orangeschool.orangeschoolapiserver.domain` 패키지 사용은 모놀리식 구조의 잔재

## 권장사항

1. **인터페이스 도입**: 도메인 간 통신을 위한 인터페이스 계층 도입
2. **이벤트 기반 통신**: 도메인 간 직접 참조 대신 이벤트 기반 통신 고려
3. **공통 도메인 분리**: 여러 도메인에서 공통으로 사용하는 엔티티는 shared 모듈로 분리
4. **단계적 리팩토링**: 
   - 1단계: 레거시 import 경로를 새로운 도메인 모듈 경로로 변경
   - 2단계: 도메인 간 의존성을 인터페이스로 추상화
   - 3단계: 이벤트 기반 아키텍처로 전환

## 즉시 수정이 필요한 사항

1. `com.orangeschool.orangeschoolapiserver.domain` 패키지 경로를 각 도메인 모듈의 올바른 경로로 변경
2. 순환 의존성이 있는 경우 즉시 해결
3. 도메인 간 직접적인 repository 접근을 서비스 계층을 통한 접근으로 변경
